# Binder: закрытый клуб коллекционеров Pokémon TCG

Chrome-расширение (Manifest V3): цифровой альбом настоящих карточек пользователя. Пользователь фотографирует свои карты, ИИ их распознаёт, приложение показывает цены и графики, коллекции друзей, собирает колоду из своих карт и даёт играть с другими.

Язык интерфейса: русский.

## Принятые решения

### Платформа и доступ
- Только Chrome-расширение, не сайт: нужен закрытый круг пользователей.
- В Chrome Web Store не публикуем. Расширение раздаётся папкой сборки и ставится через «Загрузить распакованное» в режиме разработчика. Постоянный ID `gjbcclblodnhenbfjgfbbjhdmmmpenfh` задаёт поле `key` в манифесте (`wxt.config.ts`), этот же ID указан в OAuth-клиенте Google. Приватного ключа нет: для такой установки он не нужен.
- Обновления сами не приходят: новую сборку распаковывают поверх старой папки и жмут «Обновить» на `chrome://extensions`.
- Вход через Google и код приглашения. Настоящая защита на сервере: белый список (коллекции `members` и `invites`, см. «Вход и приглашения») и правила Firestore, которые пускают только тех, кто в списке. Код расширения считаем публичным, его можно распаковать.
- Интерфейс: поп-ап расширения (вход, главная, сканирование, настройки) и страницы расширения во вкладке (главная, альбом, сканер, карточка, друзья и профили, колоды, настройки, админ).

### Стек
- WXT (сборщик расширений на Vite), React 19, TypeScript. Стили: CSS-переменные и CSS Modules, без Tailwind. Маршруты вкладки: wouter с маршрутом после `#`.
- Firebase JS SDK 13.2. MV3 запрещает удалённый код, поэтому SDK упакован в сборку, авторизация берётся из `firebase/auth/web-extension`: в этой сборке нет загрузчиков `apis.google.com` и reCAPTCHA.
- npm 11 спрашивает про скрипты установки. В `package.json` (`allowScripts`) запрещены скрипты у `@firebase/util` (пишет конфиг для Firebase App Hosting), `protobufjs` (нужен только в Node) и `re2` (нативный модуль для эмулятора Hosting, его подключают как необязательный).
- `firebase-tools` и `@firebase/rules-unit-testing` стоят в devDependencies: версия CLI и эмулятора зафиксирована в проекте.
- Шрифты лежат в расширении (`@fontsource`, только woff2, латиница и кириллица), без запросов к Google Fonts.
- Версии пакетов фиксируются точно (`--save-exact`). При установке не брать релизы младше двух недель: `npm install --before <дата>` действует на всё дерево зависимостей.

### Вход и приглашения (шаги 4–6 сделаны)
- Вход (`src/lib/auth.ts`): `chrome.identity.getAuthToken` → `GoogleAuthProvider.credential(null, token)` → `signInWithCredential`. Интерактивный токен всегда берёт service worker, потому что окно согласия закрывает поп-ап. Вкладке и открытому поп-апу он отдаёт токен, и в Firebase они входят сами. Если поп-ап успел закрыться, входит сам service worker и открывает главную вкладки (`#/home`).
- Сессия Firebase лежит в IndexedDB и общая для поп-апа, вкладки и service worker. Пока она не восстановлена, статус `loading` и данные не читаются (`src/lib/auth-state.tsx`). Выход сбрасывает токен в кэше Chrome, следующий вход идёт без окна согласия.
- Аккаунт берётся из профиля Chrome. В Edge и других браузерах без `getAuthToken` вход не работает. Если кому-то понадобится выбирать аккаунт, запасной путь — `launchWebAuthFlow`.
- `members/{uid}` (`displayName`, `photoURL`, `joinedAt`, `invitedBy`, `inviteCode`, `invitesLeft`, `lastInvite`, необязательные `showcase` — см. «Друзья и профиль» — и `role`): участник и его профиль, есть документ — есть доступ. Участники видят друг друга, остальные — только свой документ. `displayName` и `photoURL` хозяин меняет сам (`src/lib/profile-edit.ts`, см. «Друзья и профиль»): имя 1–80 символов; фото — ссылка до 2048 символов (фото из Google) или своё фото прямо в `photoURL`: квадрат 192 px в WebP, data URL до 32 000 символов (Storage нет; правило `ownPhoto` пускает только вид `data:image/webp;base64,…`). Вход их не перезаписывает: имя и фото из Google пишутся только при вступлении (`profileFrom`), и при вступлении фото — по-прежнему ссылка до 2048 символов.
- `invites/{code}` (`createdBy`, `createdAt`, `usedBy`, `usedAt`): одноразовый код, живёт 14 дней. Прочитать его может любой вошедший, если знает код целиком: так приложение объясняет отказ ещё до записи, а 31^8 вариантов не перебрать. Списком видны только свои коды.
- Вступление — одна пакетная запись: код помечается использованным и создаётся участник. Выпуск кода — тоже одна запись: новый код и `invitesLeft` минус один. Правила сверяют обе половины через `get`/`getAfter`. Новичок получает 3 приглашения (из макетов).
- Код: 8 случайных символов без 0/O/1/I/L, вид `XXXX-XXXX` (`src/lib/invite-code.ts`). Вариант `BNDR-7K2Q` из макета профиля не берём: если приставка постоянная, случайных символов остаётся 4, их можно перебрать, а ограничивать попытки правила не умеют.
- Роль — поле `role` в `members/{uid}`: `"admin"` или `"user"`, без поля — обычный участник (`Role` в `src/lib/membership.ts`). Себе роль поставить нельзя: правила пускают правку своего документа только по спискам полей (имя и фото, приглашения, витрина), и `role` в них нет; вступить сразу с ролью тоже нельзя. Роль другого участника меняет админ (только `role`, только `admin`/`user`), свою — нет, чтобы клуб случайно не остался без админа. Админ, которого убрали из `members`, ничего не может. Что может админ, см. «Админ». Первый участник (владелец) создаётся в консоли вручную: документ `members/<uid>` со всеми полями выше, `invitedBy`, `inviteCode` и `lastInvite` равны null, и `role: "admin"`.
- Код с экрана входа лежит в `chrome.storage.session`, пока идёт вход. Если поп-ап закрылся из-за окна согласия, экран вступления во вкладке подхватит код и отправит сам.
- Во вкладке вход и вступление — карточка по центру (`src/app/AuthGate.tsx`): веер карт и форма, как на экране входа поп-апа; уже 720 px веер ложится полосой сверху. Код приглашения можно ввести уже на экране входа во вкладке: он, как в поп-апе, ждёт конца входа в `chrome.storage.session`, и экран вступления отправляет его сам. Ошибка проверки членства (с «Обновить страницу») и «Firebase не настроен» — `EmptyState variant="page" tone="error"`.
- Членство отслеживается живой подпиской на свой документ в `members` (`src/lib/membership-state.tsx`): вступил или удалён в консоли — экран меняется сам.
- Карточка «Пригласить в клуб» живёт на странице «Друзья» во вкладке, как в макете профиля: в поп-апе для неё нет места. В настройках (поп-ап и вкладка) показан только остаток приглашений.
- Правила лежат в `firestore.rules`, тесты в `tests/rules`, 102 случая в пяти файлах. `profile.test.ts` — 9 случаев правки своего профиля (настоящий `saveProfile`: своё фото и имя, предел ровно 32 000, возврат фото Google и «без фото», чужой профиль, своё фото при вступлении); проверено, что они ловят снятый предел своего фото, снятую проверку вида `data:image/webp;base64,`, своё фото без проверки имени и фото вместе с `invitesLeft` или `role`. `admin.test.ts` — 15 случаев ролей, ключей клуба и действий админа (настоящие `setRole`, `saveClubKeys`, `readClubKeys`, `setInvitesLeft`, `removeMember`, `joinWithInvite`); проверено, что они ловят роль, поставленную себе, вступление сразу админом, смену админом своей роли, любое значение роли, админа без роли, роль вместе с другими полями, открытое чтение ключей, удаление админом самого себя и непроверенный десятый ключ. `firestore.test.ts` — 49 случаев (участники, коды, альбомы с языком, состоянием и картами вне базы, цены TCGdex и JustTCG), в том числе настоящие функции вступления, выпуска кода, добавления, удаления и правки карт, поиска карты у друзей и чтения цен японских карт из общего кэша. `showcase.test.ts` — 11 случаев витрины и чтения альбома друга (настоящие `saveShowcase`, `clubMembers`, `clubMember`, `loadAlbum` с дочитыванием). `decks.test.ts` — 18 случаев колод (чтение участниками, запись только хозяином, форма имени и состава, неизменный `createdAt`, удалённый участник). Если задать `RULES_FILE=<копия правил>`, тесты прогонятся на изменённой копии: так проверяется, что они ловят дыру (проверено на снятом сроке кода, открытом списке участников, записи в чужой альбом, записи цен посторонними, снятой проверке языка и напечатанного, смене языка после добавления; у витрины — на снятом пределе в шесть карт, записи чужой витрины, непроверенном элементе, повторах, счётчике приглашений вместе с витриной и витрине при вступлении; у колод — на снятой проверке хозяина, открытом чтении, снятых пределах записей, значений и имени, свободной смене полей и непроверенном времени создания).

### Бэкенд
- Firebase: отдельный проект `binder-54fb1`, не тот, что у расширения рейтинга фильмов (`movielistdb-13208`, свои лимиты и правила).
- Firebase Storage не используем: для новых бакетов нужен тариф Blaze.

### Карты и цены (решено в фазе 2)
- Справочник карт — TCGdex (https://tcgdex.dev, `src/lib/tcgdex.ts`): бесплатный, без ключа, разрешает запросы из расширения, свежие сеты есть. В Firestore справочник не храним: это экономит десятки тысяч записей при заливке (лимит Spark — 20 тысяч в день) и чтения при каждом скане. Ответы TCGdex кэшируются в IndexedDB (`src/lib/kv-cache.ts`): список сетов и сеты — 7 дней, карточки — 30 дней.
- Отказались от pokemontcg.io: его API выключают 1 марта 2027 года, новые ключи уже не выдают. Его преемник Scrydex платный (от $29 в месяц).
- Карты TCG Pocket в TCGdex цифровые (сеты `P-A`, `A1`…`B2a`, картинки в `/tcgp/`), из поиска они отсекаются.
- Язык карты (`src/lib/languages.ts`): en, fr, de, it, es, pt, ru, ja, zh-tw, zh-cn, ko, id, th, other. Международные издания (en, европейские, ru) сверяются с английским каталогом TCGdex как та же карта. У ja, zh-tw, id, th свои каталоги TCGdex со своими сетами и номерами. Карт zh-cn и ko в TCGdex нет, их добавляют как есть. Язык other (модель не узнала) даёт только подсказки из английской базы, сама такая карта не узнаётся. Привязка документов альбома к каталогу выводится из языка (`catalogFor`): менять её можно только вместе с переносом записанных карт.
- Альбом: `members/{uid}/cards/{docId}` (`setId`, `count` 1–999, `variant` normal/holo/reverse, `condition` LP/MP/HP/DMG — у Near Mint поля нет, `lang`, `addedAt`, `updatedAt`). `docId` у английской карты — ID в TCGdex (`sv03-125`), у остальных — с языком (`SV2a-094_ja`, `sv03-125_fr`). Документы фазы 2 без `lang` считаются английскими. Данные карты не дублируются: имя и картинка берутся из сета TCGdex, один запрос на сет. Карта, которой нет в TCGdex, хранит напечатанное: `printed` (`name`, `englishName`, `number`, `total`, `setCode`), ID `x-{язык}-{код сета}-{номер}` (`x-ja-MBG-3`), чтобы повторный скан добавил копию. Язык и `printed` после добавления не меняются. Альбомы видны всем участникам, менять свой может только хозяин; в альбоме «−» убирает копию, последнюю — со второго нажатия.
- Второй источник сканов — Limitless TCG (`src/lib/limitless.ts`): все японские карты, включая стартовые наборы, которых нет в TCGdex, и японские карты, у которых в TCGdex нет скана (например, `M2a`). Картинки на CDN: японские `…/tpc/{SET}/{SET}_{N}_R_JP_{XS|SM|LG}.png` (номер без нулей), английские `…/tpci/{SET}/{SET}_{NNN}_R_EN_{…}.png` (сокращение сета из TCGdex, например `MEP`). Карточка в JSON: `https://limitlesstcg.com/api/cards/{SET}/{N}?lang=jp` (и `?translate` для английского имени), CORS `*`, ключ не нужен. Это адрес их собственных подсказок, он может поменяться без предупреждения; запросы идут только при скане японской карты, которой нет в TCGdex. Найденные карты кэшируются на 30 дней, отсутствие — на сутки. Поиск по имени и номеру — страница `https://limitlesstcg.com/cards/jp?q=メガゲンガー n:3` (синтаксис поиска: https://limitlesstcg.com/cards/syntax). Она отдаёт HTML без CORS, поэтому у расширения есть `host_permissions` на `https://limitlesstcg.com/*` (`wxt.config.ts`). Японский поиск понимает только японские имена. Порядок показа (`src/ui/CardImage.tsx`): скан TCGdex → скан Limitless → вырезка из своего фото → табличка с именем и номером. Скан Limitless для карты вне TCGdex показывается только после сверки имени: при неверном коде сета по коду и номеру нашлась бы чужая карта.
- PriceCharting (там есть сканы и цены японских стартовых наборов) не используем: сайт закрыт проверкой Cloudflare, автоматические запросы получают 403, а их API платный, с токеном.
- Цены японских карт в долларах — JustTCG (https://justtcg.com, `src/lib/justtcg.ts`, спецификация `https://justtcg.com/docs/swagger.json`): данные TCGplayer, игра `pokemon-japan`, заголовок `x-api-key`, CORS открыт. Бесплатный ключ: 1000 запросов в месяц, 100 в день, 10 в минуту, до 20 карт в пакетном `POST /v1/cards`. Ключи общие для клуба (см. следующий пункт), участникам вводить ничего не нужно. Карта ищется по коду сета: у TCGplayer название сета начинается с кода («MBG: MEGA Starter Set Mega Gengar ex»), список сетов кэшируется на неделю. В сете карта ищется по английскому имени, потом по номеру «003/021», потом листаются три страницы. Английское имя японской карты TCGdex берётся из Limitless.
- Общий кэш этих цен (`src/lib/jp-prices.ts`): `prices/jt_{КОД СЕТА}`, `cards.{номер без нулей} = {d, j, n, v}` — день, ID карты в JustTCG, её имя и цены Near Mint по печатям; история — в `months`, как у TCGdex. Освежает тот участник, кому карта понадобилась первой за сутки, по ключам клуба: известные карты одним пакетом на 20, новые — поиском, один раз. Если ключей нет или у всех кончился лимит, видна последняя известная цена. Запись описывает карту в базе под кодом и номером, а не чью-то карту: у карты, добавленной как есть, цена берётся, только если её английское имя совпало с именем в JustTCG.
- Ключи JustTCG клуба (`src/lib/club-keys.ts`): документ `config/justtcg` = `{items: [{key, label, enabled, addedAt}], updatedAt, updatedBy}`, до 10 ключей по порядку. Читают все участники (запросы к JustTCG идут из их браузеров, поэтому ключи видны любому участнику в DevTools), пишет только админ, весь список одной записью. Клиент читает документ раз в 5 минут на страницу (`activeClubKeys`).
- Очередь ключей (`call` в `src/lib/justtcg.ts`, состояние — `src/lib/justtcg-keys.ts`): запрос идёт с первого включённого ключа, который не отложен. На `DAILY_LIMIT_EXCEEDED` и `REQUEST_LIMIT_EXCEEDED` ключ откладывается до полуночи UTC (месячный лимит сбрасывается в день создания аккаунта JustTCG, его Binder не знает, поэтому такой ключ пробуется раз в сутки), на `RATE_LIMIT_EXCEEDED` — на минуту, неподошедший ключ — насовсем; запрос повторяется со следующего ключа. Нет связи или сбой у JustTCG — следующий ключ не пробуется. Отложенные ключи и остаток запросов (из `_metadata` ответов v1, у ответов v2 его нет — тогда минус один) помнит каждый браузер в `chrome.storage.local` (`justtcgKeyState`), в Firestore это не пишется. Старый личный ключ из настроек (`justtcgKey`) админ может перенести в общий список.
- Рынок карты для страницы карточки (`src/lib/card-market.ts`): один запрос к бете `GET /v2/cards` с `graded=include&include=periods.30d,periods.90d,price_history.1y` на карту в сутки, ответ — в IndexedDB этого браузера (`market:…`). Английская карта ищется по ID товара TCGplayer из карточки TCGdex (`pricing.tcgplayer.*.productId`), японская — по ID в JustTCG из кэша цен японских карт (`japaneseMarketId`). Из ответа берутся цена Near Mint своей печати, история по дням за год, изменение за 30 дней и цены в грейде: только по настоящим продажам слаба за 90 дней (потом цена устаревает и показывается как последняя продажа). Пока идёт бета, `graded=include` стоит как обычный запрос.
- Внутренний адрес TCGplayer (`mpapi.tcgplayer.com/v2/product/{id}/pricepoints`) отдаёт цену без ключа; официальный API TCGplayer закрыт для новых разработчиков. Пока не используем.
- Цены берутся из карточки TCGdex: `u` — рыночная цена TCGplayer в долларах (вариант печати подбирается: holofoil для голо-карт, normal для обычных), `e` — тренд Cardmarket в евро. У японских карт TCGdex знает только Cardmarket; доллары им добавляет JustTCG (см. ниже), а карты без долларов идут в итогах альбома отдельной строкой в евро. У международных изданий на других языках показывается цена английской карты с пометкой. У похожих карт (язык other) и карт вне TCGdex цены нет. Истории у TCGdex нет, её копим сами с 20 ноября 2026.
- Своего сервера для цен нет (`src/lib/prices.ts`). Цену карты освежает тот участник, кому она понадобилась первой за сутки (UTC): сначала смотрится кэш браузера на сегодня, потом общий кэш клуба `prices/{setId}` (`cards.{cardId} = {u, e, d}`, одно чтение на сет; у неанглийских каталогов ID документа с языком, `prices/ja_SV2a`), и только устаревшее запрашивается у TCGdex. Свежая цена сразу пишется в общий кэш и в историю `prices/{setId}/months/{ГГГГ-ММ}` (`{cardId}.{ДД} = {u, e}`) для будущих графиков.
- Цена одной записи: запросов к TCGdex — не больше числа разных карт в альбомах клуба в сутки, чтений Firestore — около числа сетов на участника в сутки, записей — две на сет в сутки. Всё укладывается в бесплатный Spark.
- Слабое место: цены может записать любой участник, правила проверяют только форму документа. В клубе друзей это приемлемо. Если понадобится строже или нужна история без пропусков в дни, когда никто не заходил, — ежедневная задача в GitHub Actions с Admin SDK, а цены для участников станут только для чтения.

### Распознавание карточек
- Ключ DeepSeek вводит сам пользователь (в настройках или прямо в сканере). Он хранится только в `chrome.storage.local` этого браузера и проверяется бесплатным `GET /models`.
- Та же модель оценивает состояние карты по нескольким фото (см. «Страница карточки»).
- Модель `deepseek-flash` (DeepSeek-V4.1-Flash-1017, сверено с api-docs.deepseek.com 20 ноября 2026): `POST https://api.deepseek.com/chat/completions`, картинка частью `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…","detail":"high"}}`, `response_format: {"type":"json_object"}`, размышления выключены (`thinking: {"type":"disabled"}`). Цена $0.15 (вне пика) / $0.30 за миллион входных токенов. Запросы из расширения DeepSeek разрешает сам, отдельных прав не нужно (`src/lib/deepseek.ts`).
- Фото перед отправкой уменьшается до 1600 px по длинной стороне и сжимается в JPEG (`src/lib/photo.ts`). На одном фото может быть несколько карт.
- Схема гибридная: модель читает имя как напечатано (и английское имя), номер, число после дроби, код сета, язык, голо и рамку карты на фото (углы в тысячных долях). Язык страхуется письменностью имени: кана — ja, хангыль — ko, тайское письмо — th, кириллица — ru. Точная карта, скан и цена берутся из TCGdex в каталоге языка карты (`src/lib/catalog.ts`): по коду сета и номеру (на японских картах код сета — это ID сета TCGdex, «SV2a»), по имени и номеру, запасной путь — сеты с тем же числом карт и похожим именем. Номер сверяется строго: `localId=eq:…`. Японская карта, которой нет в TCGdex или которая нашлась неуверенно, ищется в Limitless: по коду сета и номеру, а если так не нашлась — по имени и номеру. Если та же карта есть и в TCGdex, Limitless только подтверждает её имя. Кандидаты оцениваются по похожести имени, совпадению числа карт и кода сета (`src/lib/matching.ts`): от 0.82 и с отрывом от второго — узнана сразу, иначе до трёх вариантов на выбор и «Ни одна не подходит».
- Сверка имени (`nameVerdict`): если карта и база на одном языке и имя прочитано той же письменностью, решает напечатанное имя; иначе сравниваются английские имена; если сравнить нечего — `null`. Сравнивается меньшее из похожести целиком и похожести без «Mega»/«M»/«メガ» и механик (`namesMatch`). Карта с тем же номером и похожестью имени ниже 0.5 отбрасывается: это чужая карта, обычно из-за неверного кода сета. Код сета модель читает плохо (он мелкий), поэтому в подсказке ей велено возвращать null, а не угадывать.
- «Распознано, NN%» — меньшее из уверенности модели и оценки сверки с базой.
- Карту, которой нет ни в одной базе, можно добавить как есть: в альбом идёт напечатанное, цены нет. Если база не ответила, сканер предлагает «Искать снова».
- Логика сканера одна для поп-апа и вкладки (`src/scan/useScan.ts`), а вид у каждого свой. Поп-ап: `src/scan/ScanFlow.tsx`, по одной карте, внизу «Пропустить / Добавить N». Вкладка (`#/scan`, `src/app/pages/ScanPage.tsx` и `src/scan/ScanDesk.tsx`) до фото показывает зону перетаскивания во всю ширину, после — две колонки. Слева фото с номерами карт поверх рамок от модели: номер ведёт к карте в списке, наведение на карту выделяет её рамку. Справа нумерованный список всех карт (`useScan().items`, у карты есть `photoId`) с выбором вариантов, внизу липкая «Добавить N в альбом». Уже 860 px — одна колонка. Фото можно перетащить на главную поп-апа или на страницу сканера, а во вкладке ещё и вставить из буфера (Ctrl+V).

### Страница карточки (фаза 3)
- Маршрут `#/card/{docId}` (ID документа альбома, через `encodeURIComponent`): `src/app/pages/CardPage.tsx`. Открывается нажатием на карту в альбоме и на недавнюю карту в поп-апе (вкладка открывается сама).
- Слева, по макету `Card`: большая карта (`src/ui/TiltCard.tsx`) наклоняется за курсором, блик идёт за курсором, у голо и реверса — радужный перелив. Позиция курсора — в CSS-переменных, углы зарегистрированы `@property`, чтобы карта плавно возвращалась в покой. При «уменьшить движение» и в теме Ретро карта стоит ровно, без блика, в Ретро — с жёсткой тенью. Нажатие открывает просмотр во весь экран (`src/ui/CardViewer.tsx`): нативный модальный `dialog`, `closedby="any"` и запасной клик по подложке, Esc, страница под окном не прокручивается. Переключатель «Официальный скан / Моё фото» виден, только если есть и скан, и своё фото. Счётчик копий (`addOne`, `removeOne`; последняя копия — со второго нажатия, потом возврат в альбом), состояние карты (`setCondition`) и под ними «Добавить в колоду». Левая колонка липкая (`position: sticky`) в окне от 1040 px шириной и от 820 px высотой.
- Справа: метки (тип с цветной точкой, редкость, голо, язык), имя, английское имя японской карты, сет · номер · художник. Цены: без грейда (доллары, иначе евро), Cardmarket в евро, «Мои копии» по текущей цене — только при двух копиях и больше (при одной сумма совпала бы с ценой карты). «История цены» 1М/6М/1Г — за год из JustTCG (`src/lib/card-market.ts`), а если её нет (нет ключей, карты нет в JustTCG), — из общего кэша клуба (`src/lib/price-history.ts`, месяцы читаются с ноября 2026, не раньше). Меньше двух точек — объяснение вместо графика, с причиной от JustTCG (нет ключей, кончился лимит). Наведение мышью или пальцем (`ChartPlot` в `CardPage.tsx`, точки — `chart.points`, ближайшая — `nearestPoint`) показывает пунктирную вертикальную линию, точку и подсказку с датой и ценой; у правого края подсказка встаёт слева. С клавиатуры график — `role="slider"` по дням: стрелки, Home, End, Esc, день и цену объявляет `aria-valuetext`. Изменение «за месяц» у цены — `periods.30d` из JustTCG. «Цены в грейде» — слабы PSA, BGS, CGC и других с ценой и датой последней продажи, до 8 и «Показать все»; у карт без привязки к JustTCG (похожие, каталоги без долларов) блока нет. У международных изданий на других языках — цены английской карты с пометкой. «О карте»: способности, атаки со стоимостью, HP, стадия, слабость, сопротивление, отступление, регуляция, варианты печати, турниры, сет, номер, язык (`src/lib/card-facts.ts`). У японских карт — переключатель «Перевод / Оригинал»: английский текст из Limitless (`?translate`), у карты вне TCGdex — только после сверки имени. «Есть у друзей» — обычная панель, как остальные справа; `friendsWithCard`: список участников и по одному чтению их альбома.
- Из макета не сделано, потому что нет данных: «Последние продажи» (JustTCG отдаёт только итоговую цену слаба и число продаж). Кнопку «Отметить для обмена» не делаем: обмена нет (см. «Друзья и профиль»). «Добавить в колоду» сделана (см. «Колоды»).
- Имена: английское — главное везде (страница карточки, альбом, поп-ап, сканер), напечатанное (японское и т. п.) — подписью или во всплывающей подсказке (`displayNames` в `src/lib/names.ts`). У карт вне базы английское имя из скана, у японских карт TCGdex — перевод Limitless (`englishNameOf`: один запрос `?translate`, кэш 30 дней, по 4 запроса за раз). Японский текст помечается `lang` (`htmlLang`), чтобы браузер брал японский шрифт.
- Оценка состояния ИИ (`src/lib/grading.ts`, `src/app/pages/ConditionGrader.tsx`): кнопка «Оценить состояние по фото» под состоянием. Обязательны три фото — лицо прямо, рубашка прямо, лицо под углом к свету (царапины); углы крупно — по желанию. Все фото одним запросом к DeepSeek (`askVision` в `src/lib/deepseek.ts`, общий со сканером), каждое подписано ракурсом. Модель отвечает по шкале TCGplayer: состояние, уверенность, заметки по углам, краям, поверхности и центровке, итог, каких ракурсов не хватило (ячейка подсвечивается: «ИИ просит это фото») и одна ли карта на фото. При сомнении между двумя оценками велено ставить нижнюю. Сохраняет человек кнопкой «Сохранить: …», ручной выбор остаётся. Фото уходят только в DeepSeek и после закрытия окна забываются.

### Альбом во вкладке (фаза 3)
- Маршрут `#/library`: `src/app/pages/Library.tsx`, части — в `src/app/pages/library/`. Три вида, как в макете `Library`: «Биндер» (по умолчанию), «Сетка» (по сетам; при сортировке не по номеру — одной сеткой), «Список» (таблица: карта, сет, язык, печать, состояние, копии, цена; на узком экране прокручивается сама таблица).
- Загрузка и ошибка (`Library.tsx`). Пока альбом не пришёл из Firestore, вместо стоимости и счётчиков — заглушки, а вместо разворота, сетки или списка — заглушки той же формы и «Прогресс сетов» (правила `skeleton*` в `Library.module.css` повторяют размеры `BinderSpread`, `CardGrid`, `CardList` и `SidePanels`: меняется раскладка — правятся и они). Когда альбом пришёл, а сеты TCGdex ещё грузятся, число карточек и сетов уже настоящее, заглушка остаётся только на месте стоимости. Если альбом не загрузился — экран с причиной по коду Firestore (`albumErrorMessage` в `src/lib/collection-state.tsx`) и «Обновить»: она заново открывает подписку (`retry` из `useOwned`), вкладка не перезагружается. Пустой альбом — экран `EmptyState variant="page"` с кнопкой «Добавить карточки», без шапки со стоимостью.
- Разворот биндера (`BinderSpread.tsx`): две страницы по 9 карманов (3 × 3) и корешок с кольцами, листается кнопками и стрелками ← →. Если выбран один сет, сортировка по номеру и других фильтров нет, разворот повторяет настоящий биндер сета: все карты из списка сета TCGdex по порядку, у недостающих — пустой карман с номером и бледным именем, копии на других языках рядом. Иначе карманы заполняются найденными картами подряд. На узкой панели страницы встают друг под другом, корешок ложится между ними.
- В развороте «Весь альбом» и в подборке по фильтрам при сортировке по номеру граница сетов видна закладкой над картой (`BinderSpread.tsx`, `setStartsOf`): у первой карты сета — имя сета с чертой цвета акцента, у первой карты страницы, если сет продолжается, — бледнее и без черты. В остальных карманах строка закладки пустая той же высоты. У одного сета и при сортировке по цене или дате закладок нет.
- Подпись карты в развороте и сетке (`library/AlbumCard.tsx`): имя до двух строк (место под вторую держится всегда, цены в ряду на одной высоте), цена отдельной строкой ниже, полное имя в подсказке (у японских карт — и напечатанное). Подпись недостающей карты в биндере сета — тоже в две строки.
- Фильтры и сортировка — `src/lib/library-filters.ts` (без интерфейса, тесты `tests/unit/library-filters.test.ts`): сет (группа альбома, `setKey`), язык, тип, редкость, печать (без поля — обычная), состояние (без поля — NM), цена есть/нет, поиск по английскому и напечатанному имени и по сету (имя или код: «Surging Sparks», «SV2a», «MBG») без регистра и диакритики, цифрами — по номеру; слово из одних цифр в сете не ищется: «151» находит карту № 151, а не весь сет «151». Сортировка: по номеру (сеты от новых к старым, карты вне базы в конце), по цене, по дате добавления. Доллары и евро между собой не сравниваются: сначала карты с ценой TCGplayer, потом только с Cardmarket, без цены — всегда в конце. Язык, состояние и цена показываются, только если делят альбом хотя бы на две части.
- Панель фильтров (`library/FilterBar.tsx`) раскладывается по своей ширине (container query): от 1100 px — одна строка (поиск, сет, тип, редкость, печать, «Ещё фильтры» с языком, состоянием и ценой, сортировка); уже — поиск, «Фильтры», лента чипов и сортировка, все списки в раскрывающейся панели (не `dialog`); до 600 px — две строки до карт. Включённые фильтры видны чипами с крестиком и «Сбросить»; поиск чипом не дублируется.
- Значок языка в углу карты (`CardImage`) только у неанглийских карт: английских в альбоме большинство (решение владельца 21 ноября 2026).
- Тип и редкость есть только в полной карточке TCGdex, не в сете: `src/lib/useCardFacets.ts` берёт их из общего загрузчика сведений о картах (см. «Колоды»), частями; у японских карт вне базы — из текста Limitless после сверки имени. На холодном кэше списки типов и редкостей заполняются несколько секунд.
- Фильтры и открытый разворот хранятся в `sessionStorage` вкладки (`binder:library`): возврат со страницы карточки их не сбрасывает. Вид запоминается в `localStorage` (`binder:library-view`).
- Боковая колонка: «Прогресс сетов» (разные номера до официального числа карт; нажатие выбирает сет) и «Дороже всего». Справа от альбома она стоит только в окне от 1280 px; уже этого уходит под альбом, и её панели встают в ряд (`SidePanels.module.css`). Кнопка «−» — `RemoveButton` в `library/AlbumCard.tsx`.
- Из макета не сделано: график стоимости и «▲ % за 30 дней», «Цены за неделю» (истории ещё мало). Фильтра «Для обмена» не будет: обмена нет. Число колод в шапке альбома и на главной поп-апа — из `useDecks(uid)`; пока колоды не пришли, число не показывается.

### Друзья и профиль (фаза 4)
- «Друзья» (`#/friends`, `src/app/pages/Friends.tsx`): слева «Что нового у друзей» — лента в широком виде (`FeedPanel layout="wide"`), справа панель «Участники» и «Пригласить в клуб»; уже 900 px — одной колонкой в том же порядке. Участники — все, кроме себя, по имени (`clubMembers` в `src/lib/friends.ts`): строка с аватаром, именем, числом карт и стоимостью альбома (как в альбоме: доллары, карты только с ценой Cardmarket — отдельно в евро), «в клубе с …» и витриной полоской; строка ведёт в профиль. Пока список грузится — скелетон; ошибка — экран с «Обновить»; если в клубе ты один — экран «В клубе пока только ты» с карточкой приглашения. Если альбом друга не загрузился, под лентой написано, чей, и «Обновить» перечитывает только его.
- Лента «кто что добавил» (`src/lib/feed.ts` без интерфейса, тесты `tests/unit/feed.test.ts`; панель `src/app/pages/FeedPanel.tsx`): своей коллекции в Firestore нет, лента строится по `addedAt` карт из альбомов, которые страница и так читает, и чтений не добавляет. На «Друзьях» строки участников отдают странице уже загруженные карты (`onViews`), второго `friendAlbum` и второго запроса цен нет; лента ждёт все альбомы. На главной лента та же, альбомы друзей — через `useFriendAlbum`. В профиле друга и в своём — «Новое в альбоме» этого участника (лента всех друзей в профиле потребовала бы читать все альбомы); свой берётся из подписки вкладки, его карты ведут на `#/card/…`. Подряд идущие добавления одного участника с перерывами не дольше 30 минут сворачиваются в одно событие («Ника: 5 новых карт из Surging Sparks»). Глагола нет: «добавила» или «добавил» по имени не угадать. У `FeedPanel` два вида: `column` (по умолчанию, профиль) — миниатюры стопкой, заход раскрывается по нажатию (до 24 карт, дальше — ссылка в профиль); `wide` («Друзья», главная) — галерея карт сразу под текстом события, до шести (до 24 по «Ещё N карт»). Пока альбомы грузятся — скелетон. Чужая карта открывается в `FriendCardViewer` (`src/app/pages/FriendCardViewer.tsx`, общий с профилем), со ссылкой на свою карточку, если такая есть. Время — `timeAgo` в `src/lib/format.ts` («10 минут назад», «вчера» по календарю, дальше недели — дата).
- Чего в ленте нет: `updatedAt` не говорит, что поменялось (копию добавили или убрали, поменяли состояние), поэтому ни лишних копий, ни удалений, ни смены состояния в ленте не видно; удалённая карта пропадает из ленты вместе с её добавлением. Свои карты на «Друзьях» не показываются.
- Альбом друга (`loadAlbum` и `friendAlbum` в `src/lib/friends.ts`, хук `src/lib/useFriendAlbum.ts`): Firestore берёт плату за каждый прочитанный документ, поэтому целиком альбом читается один раз и кэшируется в IndexedDB (`album:{uid}`). Потом дочитываются только карты с `updatedAt` не раньше последней известной (одно чтение плюс по чтению на изменённую карту) и счётчик `count()` (одно чтение). Если карт на сервере меньше, чем вышло, значит что-то удалено, и альбом читается заново; раз в 30 дней — целиком в любом случае. За минуту второй раз не читается. Цены — тем же `useCardViews`, что и в своём альбоме.
- Профиль (`#/u/:uid`, `src/app/pages/Profile.tsx`; `#/u/me` и свой uid — свой профиль) по макету `Profile`: у друга путь `‹ Друзья / {имя}` (`Crumbs`), аватар, имя, «в клубе с …», карточек, стоимость, сетов — имя и числа на одной базовой линии; вкладки «Витрина» и «Коллекция». Карты во всех блоках профиля одной величины (колонка 140 px, на телефоне 96 px, три в ряд). У друга под витриной — «Нет у тебя»: до 12 самых дорогих карт его альбома, которых нет в своём (по ID документа) и нет в его витрине; он стоит на месте «Из твоего списка «хочу»», которого в приложении нет. «Коллекция» — альбом по сетам, только для чтения. Загрузка — скелетоны (числа шапки, витрина, коллекция, документ друга); если альбом не загрузился (свой — `useOwned().error`, чужой — `useFriendAlbum`), вместо вкладок экран ошибки с причиной и «Обновить» (свой — `retry`, чужой — профиль монтируется заново и читает ещё раз); пустой альбом — экран вместо вкладок (свой — с «Добавить карточки»).
- Правка профиля — «Изменить профиль» в своём профиле (`src/app/pages/ProfileEditor.tsx`, нативный `dialog`): имя, фото («Выбрать фото» — середина картинки квадратом 192 px в WebP, «Фото из Google», «Убрать фото» — тогда первая буква имени), предпросмотр, одна запись в `members/{uid}` (`saveProfile`, правила — см. «Вход и приглашения»). Своё фото видно везде, где показывается `photoURL` участника; меню аккаунта в шапке и «Аккаунт» в настройках пока берут фото и имя из Google. В поиске шапки новое имя и фото появятся не сразу: `useClubMembers` держит список 10 минут.
- Чужая карта открывается в просмотре во весь экран (`CardViewer`), без правки: имя, номер, сет, язык, цена, копии; если такая есть и в своём альбоме — ссылка на её страницу. `#/card/{docId}` по-прежнему только для своего альбома.
- Витрина (`src/lib/showcase.ts`): поле `showcase` в `members/{uid}` — до шести ID документов своего альбома в выбранном порядке; поля нет, пока витрину не выбрали. Правила (`updatesShowcase`): менять может только хозяин и только отдельной записью, список до шести разных строк вида ID альбома; каждый элемент проверяется отдельно, циклов в правилах нет. Есть ли карта в альбоме, правила не проверяют: так можно испортить только свою витрину, а приложение пишет только карты из альбома и показывает только их; карта, ушедшая из альбома, из витрины пропадает сама. При вступлении витрину записать нельзя.
- Выбор витрины — `src/app/pages/ShowcaseEditor.tsx`: нативный `dialog`, поиск по имени, сету и номеру, дорогие карты сверху, номер места в витрине, седьмую не выбрать. В своём профиле пустые места витрины нарисованы пунктиром и открывают выбор.
- Обмена в Binder нет (решение владельца 21 ноября 2026): друзья живут в разных странах, обмен карт между ними не для этого клуба. Поэтому из макета не делаем «Предложить обмен», вкладку «Для обмена», отметку карт для обмена и подсказки «есть у друга для обмена».
- Из макета не сделано: «Вызвать на бой», вкладка «Колоды», список «хочу», число побед, события ленты «собрал сет» и «выиграл у …».

### Колоды (фаза 5)
- `members/{uid}/decks/{deckId}` (`name`, `cards` — ID документа альбома → число копий, `createdAt`, `updatedAt`): `src/lib/decks.ts`, подписка `src/lib/useDecks.ts`. Колоды видны всем участникам, менять свои может только хозяин. Правила проверяют форму: ID колоды `[A-Za-z0-9._-]{1,40}`, имя 1–60 символов, не больше 60 записей, у записи целое от 1 до 60 (не до 4: базовой энергии одной печати обычно больше четырёх; значения сверяются списком через `values().hasOnly`), `createdAt` не меняется, время — `request.time`. Состав пишется картой целиком: ID карт бывают с точкой (`sv03.5-006`), а в `updateDoc` точка значит вложенное поле.
- Проверка правил — чистая функция `checkDeck` (`src/lib/deck-rules.ts`): не больше 4 карт с одним именем (разные печати вместе, кроме базовой энергии), хотя бы один базовый покемон, ровно 60 карт, и копий не больше, чем в альбоме. Колода с нарушениями хранится, а в интерфейсе помечается неготовой с причинами; поля «готова» в документе нет, проверка считается при показе. Имя для правила — английское, если известно. ACE SPEC и Radiant (одна карта на колоду) не проверяются.
- Категория, стадия и тип энергии — из карточки TCGdex (`category`, `stage`, `energyType: Normal/Special`), у японских карт вне TCGdex — из Limitless после сверки имени (`src/lib/useDeckInfo.ts` поверх общего загрузчика, см. ниже; на холодном кэше и большом альбоме первый заход медленный). У карт без данных категория неизвестна: они идут в счёт 60 карт и правила четырёх копий, но базовыми покемонами не считаются; базовая энергия узнаётся по имени (`isBasicEnergyName`). В конструкторе такие карты видны только во вкладке «Все» и в группе «Без данных» с этим объяснением.
- Сведения о картах альбома, которых нет в сете TCGdex (тип, редкость, категория, стадия, тип энергии), грузит один загрузчик: `src/lib/card-details.ts` (без React, тесты `tests/unit/card-details.test.ts`) и хук `src/lib/useCardDetails.ts`. Карта TCGdex — из её карточки (кэш IndexedDB 30 дней), японская карта вне TCGdex — из текста Limitless после сверки имени. Удачные ответы хранятся в памяти вкладки: из альбома в колоды и обратно карточки второй раз не грузятся, а карточку, которую два места просят одновременно, грузят один раз. Неудачи не запоминаются. Не больше 6 запросов сразу, перерисовка — через каждые 12 ответивших карт. `useCardFacets` (альбом, без похожих карт) и `useDeckInfo` (колоды, с похожими) — тонкие обёртки над ним.
- Страницы: `#/decks` — список (`src/app/pages/Decks.tsx`): плитки колод, «Новая колода», у плитки меню «⋯» (`DeckMenu` в `DeckParts.tsx`, `popover="auto"` с кнопкой-вызывателем и anchor positioning, как меню аккаунта) с «Открыть конструктор» и «Удалить колоду» со второго нажатия (`useDeleteDeck`). Пусто — `EmptyState variant="page"` с картинкой колод; пока грузятся колоды или альбом — плитки-скелетоны; ошибка альбома — причина и «Обновить» (`useOwned().retry`). `#/decks/:id` — конструктор по макету `Deck` (`src/app/pages/DeckBuilder.tsx`): слева карты альбома (поиск, «Все / Покемоны / Тренеры / Энергия», «Только в колоде»; карты вне колоды не приглушены — решение владельца), справа колода по группам, проверки и статус («Колода готова к игре» или что исправить). Шире 1100 px панель колоды липкая справа; на 1100 px и уже внизу липкая полоса «N из 60», подсказка и «Состав», который открывает ту же панель в нативном модальном `dialog` снизу (`useMediaQuery(NARROW_DECK_QUERY)`, панель рисуется один раз). «+» не даёт взять больше, чем в альбоме, больше 4 с одним именем и больше 60 карт; почему — пишет строка под счётчиком в панели или в нижней полосе. Карты, убранные из альбома, — в группе «Убраны из альбома» с кнопкой «Убрать». При ошибке альбома конструктор показывает причину и «Обновить», пока грузится — скелетон.
- «Добавить в колоду» на странице карточки (`src/app/pages/AddToDeck.tsx`): выбор колоды и +1 копия, без колод — новая колода с этой картой. Здесь проверяются размер колоды, копии в альбоме и 4 копии этой печати; разные печати с одним именем сводит конструктор.
- Из макета не сделано: «Показывать недостающие» (вместо него «Только в колоде»), «Найти соперника» (бои не делаем). Плашки «есть у друга для обмена» не будет: обмена нет.

### Админ
- Страница `#/admin` (`src/app/pages/AdminPage.tsx`), пункт «Админ» в меню аккаунта виден только админу (`role: "admin"`, см. «Вход и приглашения»). Не админу страница говорит, что она только для админа; правила всё равно проверяют каждую запись. Страница во всю ширину содержимого, действия ключа — в одну строку.
- «Ключи JustTCG»: список `config/justtcg` вживую (`onSnapshot`). У ключа — название, маска `tcg_••••a1b2` с «Показать», состояние из этого браузера (остаток за день и месяц, тариф, «лимит на сегодня кончился, снова с …», «ключ не подошёл»), «Проверить» (`GET /v1/games`, один запрос), «Включён», порядок «выше / ниже», «Удалить» со второго нажатия. Сводка: сколько включено и сколько запросов осталось сегодня по ключам, которые уже отвечали в этом браузере. Форма «Добавить ключ» проверяет вид ключа (`^[A-Za-z0-9_-]{8,200}$`, тот же шаблон в правилах) и повторы; новый ключ сразу проверяется. Если в браузере остался личный ключ из прежних настроек, страница предлагает перенести его в общий список или забыть.
- «Участники»: все участники по дате вступления — имя с отметкой «админ», «в клубе с …», кто пригласил, «Сделать админом» / «Снять админа» со второго нажатия (`setRole`, у себя кнопки нет), число карточек (`getCountFromServer`, одно чтение на участника за заход), счётчик приглашений «− / +» (`setInvitesLeft`, правила пускают целое 0–99 и только это поле), «Убрать из клуба» со второго нажатия (`removeMember`: удаляется `members/{uid}`, альбом и колоды остаются в базе). Себя убрать нельзя ни в интерфейсе, ни по правилам.

### Интерфейс: общие элементы
- Выпадающий список — только `src/ui/Select.tsx`: настоящий `select` с `appearance: base-select`, кнопка, список, стрелка и галочка оформлены токенами темы; выбранный пункт — цветом выбора темы. Нужен Chrome 135+, поэтому `minimum_chrome_version` в манифесте — 135. В браузере без `base-select` остаётся обычный список.
- Модальные окна — нативный `dialog` через `showModal()` (`src/ui/CardViewer.tsx`, `ConditionGrader`, `ShowcaseEditor`, `ProfileEditor`, «Состав» колоды).
- Пустые экраны — `src/ui/EmptyState.tsx`. Без пропсов — панель в потоке страницы. `variant="page"` — весь экран раздела: по центру картинка, заголовок, пояснение и одна главная кнопка (по своему тексту, не во всю ширину). Картинки `art` — `album`, `decks`, `friends`, `error` — из простых фигур на токенах темы, без персонажей и оформления официальных карт. `tone="error"` — экран ошибки с `role="alert"`. `page` стоит у пустых разделов и ошибок загрузки во вкладке; в поп-апе (380 px) остаётся панель.
- Загрузка — `src/ui/Skeleton.tsx`: заглушки в форме будущего содержимого, чтобы раскладка не прыгала, когда придут данные. `shape="text"` занимает ровно строку окружающего шрифта (`1lh`), `card` — карта 63 : 88, `circle` — аватар, `block` — прямоугольник. Цвет — полупрозрачный цвет текста темы (в Ретро гуще). Пульсирует, при «уменьшить движение» стоит, в Ретро меняется рывками. Вокруг — `SkeletonArea` с `role="status"` и текстом для скринридера.
- `useOwned()` (`src/lib/collection-state.tsx`) кроме `cards`, `byId`, `ready` отдаёт `error` — причину по-русски, если подписка на альбом упала, — и `retry`, который открывает подписку заново. Без связи Firestore с кэшем в памяти присылает пустой снимок из кэша; он считается ошибкой «нет связи», а не пустым альбомом, и подписка остаётся открытой: со связью альбом придёт сам. Страницы, которые ждут альбом (альбом, главные вкладки и поп-апа, профиль, колоды), при ошибке показывают причину и «Обновить».
- Ссылки по умолчанию берут цвет окружения (`a { color: inherit }` в `src/theme/base.css`). Текстовые ссылки задают цвет `--link` своим классом. У аватарки (`src/ui/Avatar.tsx`) свой цвет: фото, без фото — первая буква `name` (токены `--text` на `--surface-2`, от 64 px шрифтом заголовков), без имени — значок.
- Главная вкладки (`#/home`, `src/app/pages/Home.tsx`): слева лента друзей (`FeedPanel`), справа «Моя коллекция» (стоимость, карточки, сеты, колоды), «Добавить карточки» (→ `#/scan`), «Недавно добавлены» (6 карт) и колоды (до 4, «N из 60»). Своих чтений Firestore у неё нет: свой альбом и колоды — общие подписки, участники — `useClubMembers` (память вкладки, 10 минут), альбомы друзей — `useFriendAlbum`. Загрузка — скелетоны, пусто и ошибки — `EmptyState variant="page"`. На ≤ 960 px колонки друг под другом, своя коллекция первой.
- Шапка вкладки (`src/ui/PageHeader.tsx`): логотип ведёт на главную; разделы «Главная», «Альбом», «Колоды», «Друзья» (`src/ui/sections.ts`, тесты `tests/unit/sections.test.ts`). «Боя» нет, пока бой не начат (маршрут `#/battle` остался), в нижней панели поп-апа (`src/ui/BottomNav.tsx`) его тоже нет. Навигация и поиск видны только участнику, меню аккаунта — сразу после входа, чтобы не-участник мог выйти. Свой профиль (пункт меню аккаунта) «Друзья» не подсвечивает. Внутренность шапки — по ширине содержимого, 1360 px.
- Путь к странице — `src/ui/Crumbs.tsx`: разделы ссылками (у ближайшего стрелка «назад»), сама страница — текстом с `aria-current`. Стоит в профиле друга и в сканере вкладки.
- Главная поп-апа при ошибке альбома показывает причину и «Обновить».
- Настройки есть в поп-апе и во вкладке (`#/settings`, `src/app/pages/SettingsPage.tsx`), секции общие (`src/settings/SettingsSections.tsx`): `SettingsSections` — ключ DeepSeek, тема, «Мои фото карточек» (доступен только «Не хранить», недоступные варианты хранения приглушены и помечены «скоро»; ключи JustTCG общие, их добавляет админ); `AccountSummary` — аккаунт. Проп `layout`: `popup` — колонка по макету `PopupSettings`, `page` — панель со строками «заголовок и пояснение слева, поля справа» (у панели уже 700 px — в одну колонку, container query) и сбоку панель «Аккаунт»: аватар, имя, почта, дата вступления, остаток приглашений со ссылкой на «Друзья», «Выйти из Binder».
- Меню аккаунта в шапке вкладки (`src/ui/PageHeader.tsx`): аватар со стрелкой открывает «Мой профиль», «Настройки», у админа ещё «Админ» (`useIsAdmin` в `src/lib/admin.ts` — живая подписка на свой `members/{uid}`: шапка стоит вне `MembershipProvider`), «Выйти». Нативный `popover="auto"` с кнопкой-вызывателем (`commandfor` + `command="toggle-popover"`, Chrome 135+) и CSS anchor positioning: Esc, клик мимо и возврат фокуса на кнопку делает браузер. Стрелки в меню ведёт атрибут `focusgroup` (Chrome 150+), в Chrome 135–149 — свой код (`src/ui/menu-keys.ts`), роли `menu`/`menuitem` ставятся только там. Enter, пробел и стрелка вниз на кнопке ставят фокус на первый пункт, Tab из меню закрывает его. Типы новых атрибутов — `src/ui/html-attributes.d.ts`.
- Поиск в шапке вкладки (`src/app/HeaderSearch.tsx`, логика без интерфейса — `src/lib/header-search.ts`, тесты `tests/unit/header-search.test.ts`): подсказки по своему альбому и по участникам клуба. Карты ищет тот же `matchesQuery`, что и поиск в альбоме (английское и напечатанное имя, номер, сет), участников — по имени, себя в списке нет. Карта ведёт на `#/card/{docId}`, участник — на `#/u/{uid}`. Видно до 6 карт и 4 участников; если карт больше, есть пункт «Показать все в альбоме». Enter без выбранной подсказки открывает альбом с этим запросом: `searchInLibrary` (`src/app/pages/library/useLibraryState.ts`) кладёт его в поле поиска альбома в `sessionStorage` (`binder:library`), остальные фильтры сбрасывает, вид и сортировку оставляет; уже открытый альбом получает запрос сразу.
- Поле поиска — `combobox` по шаблону WAI-ARIA со списком: фокус всегда в поле, выбранную подсказку называет `aria-activedescendant`, стрелки ходят по кругу, Esc сначала закрывает подсказки, потом стирает текст. Список — `popover="manual"` с anchor positioning: у `auto` щелчок в само поле закрывал бы список. Уже 560 px список встаёт во всю ширину под шапкой. «/» ставит фокус в поиск, если фокус не в поле ввода и не открыт модальный `dialog`. Сколько нашлось, объявляет `role="status"`. Пока не вошёл или не участник, поле выключено с подсказкой.
- Чтения поиска: подписки на свой документ участника и на альбом включаются при первом фокусе в поле и совпадают с подписками страниц (Firestore слушает одинаковый запрос один раз; `CollectionProvider` с `uid: null` не подписывается). Список участников (`clubMembers`) читается при фокусе и хранится в памяти вкладки 10 минут (`src/lib/useClubMembers.ts`), на буквы чтений нет. Цены поиску не нужны: `useCardViews(…, { prices: false })` не трогает общий кэш цен, иначе первый за сутки заход удваивал бы чтения и записи `prices/…`.
- Выход во вкладке — `leaveBinder` (`src/settings/leave.ts`), та же `signOutOfBinder`, что в поп-апе. После выхода AuthGate показывает экран входа, адрес не меняется; ключи и тема остаются в браузере.
- Тема хранится в `chrome.storage.sync`, и через `onChanged` смена во вкладке сразу видна в открытом поп-апе, и наоборот.

### Фото карточек
- По умолчанию фото нужно только для сканера и не хранится. Исключение: у карты без скана в TCGdex вырезка карты из фото (по рамке от модели, WebP шириной до 300 px, 20–40 КБ) сохраняется в IndexedDB этого браузера (`src/lib/thumbnails.ts`, хранилище `thumbs`) и служит запасной обложкой. В облако она не уходит, друзья и другие браузеры видят скан Limitless или табличку с именем.
- Опция «Мой Google Drive»: фото кладётся в Drive самого пользователя, scope `drive.file` (доступ только к файлам приложения).
- Опция «Превью в облаке Binder»: сжатое WebP около 50 КБ в Cloudflare R2. Нужны лимит загрузок на пользователя и удаление неиспользуемых превью.
- В альбоме по умолчанию показывается официальный скан, своё фото включается по желанию.

### Игра
- Бои по правилам Pokémon TCG: поздний этап, не в первой версии. Нужен realtime-сервер, который хранит состояние матча и проверяет ходы.
- Решение владельца (21 ноября 2026): бой делаем. Он рисуется на WebGL: настоящие карты покемонов на столе, ходы по правилам, и анимации — самая важная часть боя.
- Анимации атак общие, как в играх Pokémon: одна анимация на тип приёма (удар кулаком, огненный шар и т. п.), и её используют все карты, у которых есть такая атака. Каждой карте своя анимация не нужна: нужна таблица «атака → анимация». Анимации и эффекты наши собственные.
- Страницу «Бой» и раздел «Игра» в этом файле обновим, когда начнём делать бой. Пока пункта «Бой» нет в навигации, маршрут `#/battle` остался.

## Код

- `src/entrypoints/`: `background.ts` (service worker), `popup/` (поп-ап 380×600), `app/` (одна вкладка со всеми страницами, маршрут после `#`: `#/home`, `#/library`, `#/scan`, `#/card/:id`, `#/friends`, `#/u/:uid`, `#/decks`, `#/decks/:id`, `#/battle`, `#/settings`, `#/admin`; пустой и незнакомый адрес ведёт на `#/home`).
- `src/popup/screens/` экраны поп-апа, `src/app/pages/` страницы вкладки, `src/settings/` общие секции настроек для поп-апа и вкладки, `src/scan/` сканер (логика `useScan.ts`, вид поп-апа `ScanFlow.tsx`, вид вкладки `ScanDesk.tsx`), `src/ui/` общие компоненты (в том числе `Skeleton`, `EmptyState` с `variant="page"`, `Crumbs`, `Avatar`, `Select`), `src/lib/` логика без интерфейса, `src/theme/` токены, шрифты, базовые стили, `tests/unit/` тесты Vitest.
- Вкладка приложения одна. Поп-ап просит service worker открыть маршрут, тот находит вкладку через `runtime.getContexts` (без права `tabs`) или создаёт новую.
- `public/icon/` — временные иконки: знак Binder на тёмной плитке.
- Firestore подключается в `src/lib/db.ts`, отдельно от `src/lib/firebase.ts`: модуль Firestore регистрирует себя при импорте и не вырезается из сборки, а service worker базу не использует (без этого он весил бы 470 КБ вместо 82).
- Конфиг Firebase лежит в `.env` (в git не идёт). Шаблон и команда, которая выдаёт значения, в `.env.example`. `.firebaserc` задаёт проект по умолчанию для Firebase CLI.

Команды:
- `npm run dev` — dev-сборка в `.output/chrome-mv3-dev`, dev-сервер на порту 3127 (порт 3000 на машине разработчика занят). Свой Chrome WXT не открывает: сборку один раз загружают в обычный профиль через `chrome://extensions` → «Загрузить распакованное», там есть вход в Google для `chrome.identity`.
- `npm run build` — сборка в `.output/chrome-mv3`. `npm run zip` — архив этой сборки для друзей: распаковать и поставить через «Загрузить распакованное».
- `npm run check` — проверка типов, `npm test` — юнит-тесты.
- `npm run test:rules` — тесты правил Firestore в эмуляторе (проект `demo-binder`, порт 8180). Нужна Java 21. При первом запуске Firebase CLI скачивает эмулятор, около 137 МБ.
- `npm run test:live` — сверка сопоставления с настоящими TCGdex и Limitless (нужен интернет), в том числе ошибки чтения, на которых сканер уже ошибался (`tests/live/misread.live.test.ts`). Проверка JustTCG (`tests/live/justtcg.live.test.ts`) идёт, только если задан свой ключ: `JUSTTCG_KEY=tcg_… npm run test:live`, около четырёх запросов из дневного лимита. В обычный `npm test` не входит, чтобы не нагружать бесплатные сервисы. TCGdex иногда на минуту перестаёт отвечать: если упало несколько тестов с ошибкой базы, прогон повторяют.
- Выложить правила в настоящий проект: `npx firebase deploy --only firestore:rules --project binder-54fb1`. Только после зелёных тестов.

## Подводные камни

- Файлы Fontsource для одного набора символов (`cyrillic-400.css`, `latin-400.css`) объявляют шрифт без `unicode-range`. Браузер берёт только последнее объявление, и кириллица уходит в системный шрифт. Поэтому `@font-face` написаны вручную в `src/theme/fonts.css`.
- Эмулятору Firestore нужна Java 21 или новее: Firebase CLI 15 на Java 17 его не запускает. На машине стоят обе версии, в Path первой идёт 21. Терминалы, открытые до установки JDK 21, видят старый Path, их нужно перезапустить. В bash сессий Claude первой бывает Java 17; тогда перед `npm run test:rules`: `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.10002-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"`.
- Тесты правил под нагрузкой: файл, который идёт первым, платит за прогрев эмулятора, и `initializeTestEnvironment` может не уложиться в 30 с; у `tests/rules/showcase.test.ts` срок `beforeAll` — 120 с. Эмулятор на порту 8180 один: два одновременных прогона мешают друг другу.
- Порядок CSS-модулей в сборке не задан. Правило модуля общего компонента может встать после правила страницы с той же специфичностью и перебить его. Так `position: relative` у `.frame` из `CardStub.module.css` перебивал `position: absolute` у карт веера из `Welcome.module.css`, и в собранном поп-апе карты закрывали поле кода и кнопку входа. Если страница меняет свойства общего компонента через `className`, её селектор должен быть сильнее одного класса (`.fan > .fanCard`) или компонент ставится в свою обёртку. Перестановка импортов не помогает.
- Popover меню аккаунта лежит в шапке по DOM и наследует её CSS-переменные (`--focus-ring` цвета шапки, цвет текста), хотя рисуется в верхнем слое над страницей. Меню сбрасывает их на токены поверхности, иначе кольцо фокуса в теме Покемон белое на белом.
- Chrome 157 не загружает распакованное расширение по флагу `--load-extension`. Автоматическую проверку собранного расширения без окна гоняли в Edge на том же Chromium. Вход через `chrome.identity` есть только в Chrome, его проверяют руками.
- Фильтр номера у TCGdex без `eq:` нестрогий: `localId=003` находит `073`. Из-за этого первый скан японской карты MBG 003 попал на промо mep-073. Ищем только с `eq:` и сверяем номер ещё раз в коде.
- У японских карт в TCGdex часто нет скана (особенно у свежих сетов `M…`), а у стартовых наборов нет и самих карт. Поэтому нужен Limitless. Его CDN различает регистр кода сета («SV2a», «MBG»), а API отдаёт код в правильном регистре.

## Порядок работ (предварительный)

1. Каркас MV3-расширения: поп-ап, страницы во вкладке, темы, вход через Google и белый список, правила Firestore. Сделано и проверено в Chrome.
2. Сканирование: загрузка фото, запрос к модели, сопоставление с базой карт, выбор варианта, добавление в альбом. Сделано; первый настоящий скан в Chrome прошёл с ошибкой языка, исправление (языки, Limitless, обложки) ждёт проверки в Chrome.
3. Альбом и страница карточки: разворот биндера, фильтры, цены и графики. Страница карточки и альбом (разворот биндера, фильтры, сортировка) сделаны; графики стоимости коллекции ждут истории цен.
4. Друзья: профили, витрины, лента, приглашения. Сделано, в том числе правка своего имени и фото; в Chrome с настоящим Firestore лента не проверена. Обмена нет.
5. Колоды: конструктор из своих карт, проверка правил (60 карт, не больше 4 копий). Сделано; с настоящим Firestore в Chrome не проверено.
6. Бой: на WebGL, по правилам Pokémon TCG, с общими анимациями атак по типу приёма (см. «Игра»). Решение принято, работа ещё не начата.

## Открытые вопросы

- Нужна ли ежедневная задача для цен (GitHub Actions с Admin SDK), чтобы история шла без пропусков и цены были только для чтения. Пока цены освежают сами участники (см. «Карты и цены»).
- Хранение своих фото (Google Drive и превью в Cloudflare R2): в настройках эти варианты приглушены с пометкой «скоро», переключатель «Моё фото» из макета сканера не сделан. Пока вырезка из фото есть только у карт без скана в TCGdex и только в одном браузере.
- Ключи JustTCG клуба лежат в Firestore и видны всем участникам. Если понадобится их спрятать — прокси с ключами в секретах (Cloud Functions на Blaze или Cloudflare Workers), но бесплатные ключи JustTCG с облачных серверов могут получать `EXCESSIVE_FREE_TIER_USAGE`. Какой ключ упёрся в лимит, каждый браузер узнаёт сам, одним отказом; общую отметку в Firestore можно добавить, если отказов станет много.
- Корейские и китайские (КНР) карты: их нет ни в TCGdex, ни в Limitless. Корейские издания повторяют японские сеты и номера, их можно было бы привязать к японскому каталогу как похожие; не сделано.
